# 比赛日流程与操作边界

更新日期：2026-08-19。完整的逐步现场流程以
[比赛现场完整操作手册](FIELD_OPERATOR_MANUAL.md) 为准；本页保留规则和清单摘要。
用户提供的赛事现场确认优先于仓库中早期规则摘录的保守解释。
报到日期、地点、检录和调试时段仍以组委会最新通知为准。

## 已确认边界

- 总时限 15 分钟，软件暂停不暂停官方计时。
- 起点为机器狗趴卧、头朝箭头方向；站起时开始计时。
- 比赛开始、中途暂停和重启可以使用电脑。
- 电脑只用于发送 `START/CONTINUE/PAUSE/STOP` 结构化事件或重启本机服务；不得人工发送
  方向、速度、步态、姿态或原始运控命令。
- 比赛程序和全部感知/决策运行在狗内置主控；无网线、无 Wi-Fi 时也能独立运行。场地可能
  有网络，但程序不能依赖它。
- 不需要额外实体急停或语音控制。正式配置保持 `manage_dialogue=false`。
- 三个 Type-C 口定义为 `UDisk`、`charge`、`download`，实际插接按机身标识；不得猜口。
- 虚线可以踩/跨，实线不能踩/跨。跌落、出线和跳段的扣分按最新裁判解释执行。

## 电脑操作入口

比赛前和比赛中的全部选手/裁判指令均由本地 UI 发送；UI 是唯一人工入口。终端脚本保留为 UI
后端和故障恢复工具，不作为赛场日常操作界面。允许的结构化事件只有 START、PAUSE、STOP、
restart、选择赛段和 CONTINUE，不提供方向、速度、步态、原始运控或“强制赛段完成”。

跌落后由工作人员按裁判要求放回，操作者在 UI 选择裁判指定赛段并确认 CONTINUE；该操作只改变
检查点和许可，不会伪造石板、触球、过桥、四足入圈或趴下事实。终点自主条件满足后结束；裁判
要求提前结束时在 UI 使用 STOP。

在项目仓库执行：

```bash
./scripts/competition_control.sh status
./scripts/competition_control.sh start
./scripts/competition_control.sh pause
./scripts/competition_control.sh continue
./scripts/competition_control.sh restart
```

也可运行 `./scripts/start_competition_ui.sh` 使用本地控制台；XTerminal 连接参数见
[`COMPETITION_UI.md`](COMPETITION_UI.md)。默认比赛模式从后端拒绝调试移动和人工姿态；正式
比赛严禁使用 `--maintenance-controls` 启动 UI。

密码只在 SSH/sudo 交互提示中输入，不写入脚本、文档或 shell 历史。正式比赛入口不提供方向、
速度、步态和姿态参数；仓库中的维护脚本不属于比赛入口。`restart` 只恢复已保存赛段号，状态
强制回到 `DOWN_WAITING`，不会自动运动。

## 赛前携带

- CyberDog 2、原装充电设备和备用电源；
- 调试电脑、直连网线和已验证的 SSH 凭据；
- `download` 口所需的官方线材，以及仅在赛事流程要求时使用的 U 盘；
- 防滑垫、卷尺、胶带、纸笔、相机和离线仓库备份；
- 最新部署清单、真机日志路径和本检查单打印件。

## 上场前检查

- 电量足够，比赛运行时拔掉 charge 口充电线；
- 狗处于起点规定姿态，四周无人员、线缆和跌落风险；
- `mi-dog-real-sensor.service=active`，正式节点单实例；
- `manage_dialogue=false`、`enable_motion=true`，并由预检确认
  `course_calibrated=true`、`DOWN_WAITING/run_allowed=false` 和空闲 Servo 0 帧；
- 相机、雷达、odom、BMS、运控状态和检查点可读；
- `status` 返回预期状态、赛段和 `run_allowed`；
- UI 显示“正式比赛模式”，人工移动/姿态按钮均锁定；
- 已现场演练电脑 `pause` 与 `restart`，两者都不会自动恢复运动；
- 无网线、无 Wi-Fi 冷启动证据有效；若比赛时接直连网线，它只承载结构化操作，不承载算力；
- 全队知道谁操作电脑、谁观察机器狗、谁与裁判沟通。

## 正式比赛顺序

1. 将狗放到起点，拔除充电线，确认人员退出安全区域。
2. 电脑执行 `status`；异常时不开始。
3. 裁判允许后执行 `start`。只观察状态与物理结果，不发送人工运动命令。
4. 需要暂停时执行 `pause`，确认 `state=PAUSED` 且 `run_allowed=false`。
5. 需要从检查点继续时，在裁判允许且环境安全后执行 `continue`。
6. 需要重启时执行 `restart`；确认服务 active 且状态为 `DOWN_WAITING`，再由裁判允许继续。
7. 严重异常时优先保证人身和设备安全，执行 `stop` 或现场断电，并接受赛事判罚。
8. 终点判定、趴下和保持时间按最新裁判口径执行；保存日志和视频。

## 仍需技术会议记录

- 暂停和重启是否持续计时、是否扣分；
- 跌落/出线后允许放回的位置，以及是否可从当前检查点继续；
- 重启后允许使用 `continue` 还是必须重新 `start`；
- 终点四脚入圈、趴下姿态和保持时间的精确定义。
