# 比赛日流程与操作边界

本文件只采用仓库内 `extracted/competition_problem.txt` 和
`extracted/competition_rules.txt` 的规则事实。报到日期、地点、检录时刻和调试时段不在
当前赛事文件中，必须以组委会最新通知为准，不能由旧聊天记录或推测填写。

## 已知比赛规则

- 总时限 15 分钟，软件暂停不能暂停官方计时。
- 起点由机器狗趴卧、头朝箭头方向开始；机器狗站起时开始计时。
- 全程自主；设备启动后不允许再次触碰电脑，触碰电脑则比赛结束。
- 允许笔记本作为算力节点。
- 规则明确允许比赛中通过语音、触摸控制机器狗“继续比赛”。

本项目正式比赛采用狗内置计算，不使用网线或笔记本算力节点。网线仅用于赛前部署、日志和
调试，上场前拔除。systemd 在狗开机时自动启动程序并进入 `DOWN_WAITING`；裁判允许后产生
`START` 事件才开始任务。因此“进程启动”和“机器狗站起/比赛开始”是两个不同事件。
- 虚线可以踩/跨，实线不能踩/跨。
- 跌落或身体出线后，可从跌落位置或当前赛段已通过的任意位置开始，既有扣分不返还。
- 跳过赛段则该段不得分，既有扣分不返还。

## 是否需要一键启动装置

现有规则没有写“必须使用实体一键启动装置”。当前系统采用狗本机唤醒词加精确语音口令产生
`START`，并由 supervisor 边沿安全门决定是否进入 `RUNNING`。但是因为启动后不能再触碰
电脑，正式比赛前必须让裁判确认以下方案是否合法：

1. 操作者在起点说“铁蛋铁蛋—启动”是否属于允许的启动方式；
2. 头部双击用于暂停是否属于规则允许的触摸控制；
3. “恢复/重试当前赛段”是否属于规则中的“继续比赛”；
4. 独立急停装置是否可由操作者全程持有。

补充规则只明确写语音/触摸可以控制“继续比赛”，没有明确写初次 START。因此不能自行把
“允许继续”扩大为“允许语音起跑”；必须在技术会议取得裁判确认。若不允许，应按裁判指定
的本体启动方式接入同一 START 事件，不能用电脑远程启动。

若裁判要求实体一键启动，应把它接入同一个白名单 `operator_event`，只产生 START 事件，
不能绕过 supervisor、BMS、运控和传感器安全门。

## 报到前资料包

- 参赛通知、队伍和设备证件；
- 最新组委会日程与场地图；
- Git commit、机器狗部署哈希和配置哈希；
- 本仓库离线副本和 ARM64 安装包；
- 真机验收矩阵、测试数据和操作手册打印件；
- 网线、官方转接/供电附件、笔记本电源；
- 经裁判允许的急停装置和备份；
- 日志导出介质，不把密码写进资料包。

## 到场后但未检录

1. 核对比赛场地、无线限制、算力笔记本和急停规定。
2. 记录官方随机摆放规则和本轮可见的目标/障碍范围；不得预设 Gazebo 固定坐标。
3. 在允许的调试区执行无运动服务检查，确认电池、BMS、传感器和声音。
4. 只在组委会允许的时段和区域做运动测试；不在正式赛道擅自标定。
5. 把实际报到、检录、调试和比赛时间填入本文末尾的日程表。

## 检录前最终检查

- 狗不连接充电线，电量满足整场和等待余量；
- `enable_motion` 与本轮批准配置一致；
- 服务、相机、雷达、里程计、BMS、运控和 supervisor 正常；
- `DOWN_WAITING`、`run_allowed=false`；
- 唤醒、四条短口令和双击均能产生结构化事件；
- 离线五条识别播报文件存在；
- 网线已拔除；狗在无外部网络条件下冷启动后服务仍为 active；
- 由现场人员/视频确认外部 RJ45 在启动和本机口令期间确实拔除；不要用 `eth0` carrier
  推断外部插头状态，因为机内主控与运控板可能共享内部以太网链路；
- 记录当前 commit、配置和最终一次自检时间；
- 全队知道谁说启动、谁观察、谁负责急停、谁与裁判沟通。

## 上场流程

1. 按裁判要求将狗放在起点，头朝箭头，保持趴卧。
2. 确认网线已拔除；所有进程均在狗上，已自动启动并处于等待状态。笔记本不参与比赛。
3. 裁判允许开始后，使用已确认合法的启动方式。
4. 计时从机器狗站起开始；软件内部不得把暂停时间扣除。
5. 运行中只使用裁判确认的语音/触摸命令；不得通过电脑发送方向、速度或重新启动程序。
6. 发生严重风险时以人身和设备安全优先使用急停，并接受相应比赛判罚。
7. 终点要求四条腿足底都在圈内并趴下，不能只以程序进入 FINISHED 判断结束。

## 赛后

- 先确认停止输出和稳定姿态，再按裁判允许的方式接触设备；
- 导出完整日志、视频、最终状态、耗时和裁判判罚；
- 记录每段物理结果，不只记录状态转换；
- 将本轮版本和数据补入 `WORKLOG.md`、`REAL_ROBOT_TEST_DATA.md` 和验收矩阵。
