# CyberDog 2 比赛现场完整操作手册

更新日期：2026-08-19（Asia/Shanghai）  
适用项目：2026 小米杯“荒野寻宝”真机比赛  
人工操作入口：本地 Web UI  
机器狗主控：`mi@192.168.44.1`  
本手册面向现场操作者，不包含开发、刷机或绕过安全门的方法。

## 0. 先看这一页：当前是否允许上场

> **截至提交 `0f63d9a`，机器狗还不能正式自主开赛。**

当前版本是通过基础安全审计的 maintenance 版本，但真实感知仍固定发布 `facts={}`，
`course_calibrated=false`，服务也尚未冻结为 competition。必须同时满足下列全部条件，现场操作者
才可以执行本手册中的正式 START：

- 已有新的“正式比赛版”Git 提交、ARM64 构建、部署清单和回滚包；
- 六个赛段真实对象事实已经实现并逐段通过物理验收；
- 起点坐标、航向和场地随机物体已经标定；
- 起点“趴卧→起立→START”的最终动作链已经真机验收；当前 START **只开放赛段 1 许可，
  不会自动调用原厂起立动作 111**；
- systemd 服务已由技术负责人冻结为 competition，不是 maintenance；
- 狗上的 `competition_preflight.sh` 输出唯一成功结论 `PREFLIGHT=PASS`；
- 下方“比赛放行记录”已经填写并由技术负责人、操作者共同确认。

任何一项缺失，都只能进行维护或只读检查，不得点击正式 START。不得为了赶时间手工把
`course_calibrated` 或 `site_transform_valid` 改为 true。

## 1. 现场人员分工

至少三项职责必须明确，可由两人兼任，但不能无人负责：

1. **UI 操作者**：只看状态和发送白名单按钮，不发送人工方向、速度、步态或姿态比赛控制。
2. **机器狗观察员**：始终看真实机器狗、场地边界和人员，异常时立即喊“暂停”或“STOP”。
3. **裁判沟通员**：确认开始、暂停、跌落放回、恢复赛段、终点和是否允许重启。

只有 UI 操作者点击按钮。其他人通过明确口令告诉操作者，不多人同时操作电脑。

## 2. 必带物品

- CyberDog 2、原装充电器和官方线材；
- 已验证的比赛电脑、电源和直连网线；
- 已安装专用 SSH 密钥的电脑账户；
- 仓库离线副本、最新回滚包、SHA256 和部署清单；
- 本手册的离线/打印副本；
- 防滑垫、卷尺、胶带、纸笔和独立录像设备；
- 组委会允许的备用电源和工具。

三个 Type-C 口只按机身标识使用：`UDisk`、`charge`、`download`。不凭左右位置猜端口，
不在赛场临时尝试扩展坞、USB 网卡或未知转接器。

## 3. 上电前检查

1. 将狗放在平整、防滑、无台阶和无悬空边缘的位置。
2. 狗前后左右无人、无线缆缠绕、无可被撞倒物品。
3. 检查腿、脚垫、外壳、相机/雷达窗口和线缆，无松动、遮挡和明显损伤。
4. 确认狗处于稳定趴卧；不要提着或悬空开机。
5. 记录电池和充电状态。充电期间只允许开机、连接和只读检查。
6. 使用原厂规定的电源键/上电方法开机，不直接拔插主电源模拟开关机。

## 4. 上电和系统稳定

1. 开机后不要立刻发送姿态或运动操作。
2. 等待原厂 bringup 和本项目 systemd 服务稳定。相机 guard 默认等待系统 uptime 至少
   240 秒，然后按 45 秒采集、5 秒冷却循环工作。
3. 启动阶段允许相机暂时没有帧；只有预检取得实际新图像帧才算相机就绪。
4. 若服务反复重启、原厂状态异常或狗自行出现非预期动作，停止流程，不进入比赛。

## 5. 连接电脑

电脑有线地址设为 `192.168.44.100/24`，狗为 `192.168.44.1`。在仓库根目录执行：

```bash
cd "/mnt/e/Competitions during college/mi_dog/solution"
./scripts/start_competition_ui.sh
```

浏览器应打开 `http://127.0.0.1:8765/`。必须看到：

- 页面标记为“正式比赛模式”，不是“维护控制已启用”；
- 目标为 `mi@192.168.44.1`；
- “已连接”；
- 人工移动和姿态区域由后端锁定。

正式比赛**禁止**使用：

```bash
./scripts/start_competition_ui.sh --maintenance-controls
```

UI 只监听当前电脑的 `127.0.0.1`，不要把端口转发到场地网络，不要把页面令牌截图或分享。

## 6. 只读状态检查

点击“刷新状态”，逐项确认：

| UI 字段 | 正式开始前要求 |
| --- | --- |
| 服务 | `active` |
| 状态 | `DOWN_WAITING` |
| 赛段 | `1`（全新比赛） |
| 运动许可 | `false` |
| 运动总开关 | `True`，但仍受 Supervisor、传感器和课程门闭锁 |
| 电量 | 建议至少 50%；低于现场放行值不开始 |
| 运行最低电量 | 当前软件硬门为 30%，不能把它当作推荐开赛电量 |
| 有线充电 | `否` |
| 电池温度 | 正常、无过温告警 |
| 趴下安全原因 | 仅说明当前是否适合执行 101，不是 START 的完整诊断 |

技术负责人还应在电脑端执行只读审计：

```bash
./scripts/robot_read_only_audit.sh \
  --identity ~/.ssh/mi_dog_competition_ed25519
```

正常结尾必须为：

```text
READ_ONLY_TOPIC_AUDIT=PASS
READ_ONLY_AUDIT=PASS
```

只读审计正常时，空闲真实 Servo 帧必须为 0。出现重复节点、`RUNNING`、`run_allowed=true`、
传感器无样本或空闲 Servo 非零，均不得开始。

## 7. 拔充电线后的最终预检

1. 在狗保持趴卧、人员远离运动范围时拔除 `charge` 线。
2. 等待 UI 的“有线充电”变为“否”。
3. 确认运控充电状态已恢复正常。若拔线后仍残留 `motion_switch_status=14`：
   - 不重复点击 START；
   - 先按正常流程重启本项目服务；
   - 若仍为 14，使用原厂正常整机重启流程，重新等待稳定并从第 5 节开始；
   - 不改代码或参数绕过。
4. 技术负责人在狗上运行正式预检：

```bash
source /opt/ros2/galactic/setup.bash
source /opt/ros2/cyberdog/setup.bash
source /home/mi/mi_dog_ws/install/setup.bash
export ROS_DOMAIN_ID=42
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file:///etc/mi/cyclonedds.xml
/home/mi/mi_dog_ws/scripts/competition_preflight.sh
```

只有看到 `PREFLIGHT=PASS` 才能继续。预检会检查 competition 服务、课程标定、真实观测、
相机/雷达/odom、BMS、运控状态、节点单实例、空闲 Servo 零帧和安全参数。

相机处于 5 秒冷却窗口时预检可能因暂时无帧拒绝；等待下一活动窗口重新预检，不能修改新鲜度
阈值。预检失败是安全结果，不是需要“强行跳过”的故障。

## 8. 放到起点

1. 由裁判确认起点、方向、初始姿态和人员撤离时间。
2. 将狗按标定规定放在起点，头朝箭头方向，四脚和机身处于允许区域。
3. 清除网线和充电线对运动的牵拉。若规则允许保留直连网线，也必须确保不会缠绕；程序算力
   不依赖电脑或外部网络。
4. 最后一次点击“刷新状态”，确认仍为 `DOWN_WAITING/run_allowed=false`。
5. 观察员确认赛道内无人后，明确说“场地安全”。

### 起立与计时特别说明

规则记录为“起点趴卧，站起时开始计时”。当前正式 UI 故意禁止人工姿态，当前 START 也不会
调用动作 111。因此正式比赛版冻结前，必须由技术负责人和裁判确定并验收唯一的起立链：

- 方案必须仍通过 UI 触发；
- 必须明确起立和 START 的顺序及计时点；
- 起立失败不得自动进入 303 行走会话；
- 不得把 `--maintenance-controls` 作为未经批准的临场替代方案。

未冻结这条链时，本手册到此停止，不得开赛。

## 9. 正式开始

裁判允许、观察员确认安全后，UI 操作者点击一次 `START · 开始`。

START 的含义：

- 把检查点重置为赛段 1；
- 只有所有安全输入实时有效时才进入 `RUNNING/run_allowed=true`；
- 不发送人工方向、速度或“强制完成”事实；
- 被拒绝后不会在条件恢复时自动开始，必须查明原因并由裁判再次允许后重新点击。

点击后确认 UI 显示 `RUNNING`、赛段 1、`run_allowed=true`，同时观察真实狗是否按预期动作。
不要连续点击 START，不要把视频画面当作唯一物理依据。

## 10. 正常比赛中怎么操作

正常运行时操作者只做三件事：观察状态、听观察员/裁判指令、在需要时点击结构化按钮。

- 不点击维护移动键；正式模式下后端也会拒绝。
- 不发送人工姿态、方向、速度、步态或原始运控命令。
- 不手工修改赛段完成事实。
- 不在 RUNNING 时选择赛段。
- 可按需查看头部 RGB，但现场独立录像和肉眼观察优先；视频断开不代表自治停止。
- 电脑或网线断开不会自动停止狗内置自治。连接异常时不要盲目重复按钮。

## 11. PAUSE、CONTINUE、STOP 和重启的区别

| 操作 | 什么时候用 | 预期结果 | 后续 |
| --- | --- | --- | --- |
| PAUSE | 裁判临时暂停、需要检查但没有严重失控 | `PAUSED/run_allowed=false`，撤销运动许可 | 安全并获准后 CONTINUE |
| CONTINUE | 从当前已保存赛段恢复 | `RUNNING/run_allowed=true` | 不重置到赛段 1 |
| STOP | 人员/设备危险、严重失控、裁判要求结束 | `EMERGENCY_STOP/run_allowed=false`，锁存 | 必须重启服务才能离开急停 |
| 重启进程 | 软件异常、STOP 后恢复、裁判允许重启 | 先 STOP，再产生新进程，最终 `DOWN_WAITING/false` | 裁判决定 START 还是选关 CONTINUE |

### 暂停与恢复

1. 点击“暂停”一次。
2. 必须看到 `PAUSED` 和 `run_allowed=false`，并由观察员确认物理停稳。
3. 不因 UI 已变为 PAUSED 就立即靠近；确认狗实际停止后再按裁判要求处理。
4. 场地恢复安全且裁判允许后，若从原检查点继续，点击对应赛段的“确认放回点并 CONTINUE”。

### STOP

出现以下任一情况立即 STOP：人员进入危险范围、狗持续撞击/冲向边界、翻倒后仍输出、冒烟/异味、
异常高温、运动与 UI 状态明显不一致，或裁判明确要求终止。

STOP 可以绕过 UI 的普通写操作互斥立即派发，但网络完全断开时无法从电脑送达。通信丢失且有
人身危险时，不接近仍在运动的狗，按裁判和原厂设备规定执行现场紧急断电/隔离流程。

## 12. 跌落、出线和裁判放回

1. 立即 PAUSE；若仍有运动或存在危险则 STOP。
2. 确认 `run_allowed=false` 并等狗实际停稳。
3. 只有裁判/工作人员允许后才能接近和搬动。
4. 按裁判指定位置、方向和姿态放回。
5. UI 选择裁判指定的赛段 1..6。
6. 再次确认周围安全，点击“确认放回点并 CONTINUE”。
7. 该操作只保存赛段并继续，不会伪造已触球、已过桥、已进球或已完成终点事实。

如果裁判要求从头重来，使用 START；START 会明确把检查点重置为赛段 1。不要把 START 当作
普通恢复键。

## 13. UI/SSH/视频异常

### UI 显示“连接异常”

1. 不连续点击按钮。
2. 肉眼观察狗是否仍正常运行；狗内置自治不依赖 UI 持续连接。
3. 检查网线、电脑 `192.168.44.100/24` 和 `192.168.44.1`。
4. 关闭旧 UI 进程后只启动一个默认比赛 UI。
5. 必要时用 `./scripts/connect_robot.sh` 做连接诊断；它是故障恢复入口，不是日常比赛操控入口。

### 返回 409

已有一个普通写操作执行中。等待它结束，不并发重试。确有危险时点击 STOP。

### START/CONTINUE 被拒绝

读取 UI 操作记录和各状态字段；“趴下安全原因”不是 START 的完整拒绝原因。由技术负责人查看
预检/服务日志，处理充电、电量、BMS、运控状态、姿态、odom 或传感器问题，再经裁判允许重试。
系统不会在输入恢复后自行开始。

### 视频断开

关闭后重新开启一次。不要因为视频断开重启比赛或改变安全参数；以真实狗、UI 状态和独立录像为准。

## 14. 正常终点

1. 观察赛段进入 6，并以真实足球、四足入圈、停稳和趴下为准。
2. 正常完成应进入 `FINISHED/run_allowed=false`。
3. 由裁判确认终点和保持时间，不自行伪造完成。
4. 若裁判要求立即结束，点击 STOP。
5. 保存 UI 操作记录、独立视频和比赛时间。

## 15. 比赛结束后的趴下、充电和关机

1. 先确认不是 `RUNNING`，且 `run_allowed=false`。
2. 如果狗已经稳定趴卧，不再发送姿态动作。
3. 如果仍站立：等待裁判宣布本轮结束；点击 STOP，再点击“重启进程”恢复
   `DOWN_WAITING/run_allowed=false`；关闭正式 UI，重新以维护模式启动 UI：

   ```bash
   ./scripts/start_competition_ui.sh --maintenance-controls
   ```

4. 确认狗周围安全、未接充电线、`safe_to_lie_down=true` 且安全原因 `ready`，再点击一次“安全趴下”。
5. 确认原厂动作 101 完成并真实趴稳后，关闭维护 UI。
6. 需要充电时，先确认稳定趴卧，再按机身标识接 `charge`。
7. 导出日志、UI 记录、视频、部署清单和异常说明。
8. 需要关机时使用原厂正常关机流程，确认完全关机后再拔除主电源或搬运。

## 16. 现场禁止事项

- 预检未 PASS 就 START；
- 在充电时起立、趴下或运动；
- 临时修改 `course_calibrated`、`site_transform_valid`、电量门、watchdog 或传感器超时；
- 使用 `--maintenance-controls` 参加正式比赛；
- 直接发布 `safe_cmd_vel`、`motion_servo_cmd` 或原始 LCM 运控消息；
- 把 Gazebo 镜像复制到狗或运行赛事镜像中的 `scp_to_cyberdog.sh`；
- 多开 UI、多个操作者同时点击、连续重复 START/CONTINUE；
- 在仍运动时靠近、扶狗、搬狗或拔线；
- 把 UI“命令已发送”当成真实物理完成，必须看状态反馈和真实狗。

## 17. 一分钟速查卡

### 开赛

1. 平地趴卧、检查硬件、原厂方式上电。
2. 等待至少 240 秒；连接 `192.168.44.1`。
3. 启动**不带维护参数**的 UI。
4. 确认 competition 发布版、放行记录和回滚包。
5. 拔充电线；电量建议 ≥50%。
6. `DOWN_WAITING / stage 1 / run_allowed=false`，各传感器和电源字段正常。
7. 只读审计 PASS；正式预检 `PREFLIGHT=PASS`。
8. 放到标定起点；按已冻结的起立链操作。
9. 裁判允许后只点一次 START。

### 比赛中

- 临时停：PAUSE → 确认实际停稳。
- 原点继续：CONTINUE。
- 裁判放回：PAUSE/STOP → 放回 → 选赛段 → CONTINUE。
- 严重危险：STOP。
- 重启后绝不会自动继续；裁判决定 START 或选关 CONTINUE。

### 收尾

1. `run_allowed=false`。
2. 已趴卧则不重复动作；站立则赛后切维护 UI 安全趴下。
3. 保存日志、视频和版本。
4. 原厂流程充电或关机。
