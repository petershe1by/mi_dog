## 当前安全状态

- 当前 maintenance/competition 适配器为 motion-enabled，但启动时 Supervisor 为
  `DOWN_WAITING/run_allowed=false`；比赛控制器默认 `course_calibrated=false`，未标定时零输出。
- `manage_dialogue=false`，语音不会打开自定义比赛控制入口。
- 比赛不要求额外实体急停或语音控制；现有急停守卫和语音入口保留为闭锁的兼容代码。
- 比赛程序全部运行在狗内置主控，不依赖网线、Wi-Fi 或场地网络。
- 电脑可在比赛开始、中途暂停和重启时发送结构化操作事件，但不得发送方向、速度、步态或姿态命令。

## 答复后的工程门

1. 使用 `scripts/competition_control.sh` 验证电脑端 `status/start/pause/restart`，所有操作只进入
   supervisor，且 `PAUSE`、服务重启和通信中断均撤销运动许可。
2. 在 `enable_motion=false` 下完成控制链验收后，才在防护工装上做零速度
   `SERVO_START/DATA/END` 测试；不把“无额外急停要求”解释成可跳过软件停止验证。
3. R2、R8 明确后，冻结暂停/重启后的赛段恢复和计分流程。
4. R7 明确后冻结部署目录；R9 明确后冻结终点物理判定和自动安全趴下条件。

所有答复落实后，应同步更新 `PROJECT_HANDOFF.md`、`ROADMAP.md`、
`COMPETITION_DAY_CHECKLIST.md`、`REAL_ROBOT_ACCEPTANCE.md` 和 `WORKLOG.md`。
